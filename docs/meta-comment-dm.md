# Comment → DM on Meta's official APIs (Instagram first, then Facebook)

What the app does: on **Automations** a rule says *account + post + keyword → private reply text*.
When a comment on that post contains the keyword (whole word, any capitalisation), the app sends the
commenter **one** message through Meta's **Private Replies** endpoint
(`POST /{ig-user-id}/messages` with `recipient.comment_id`, or `POST /{page-id}/messages` for a Page).
Meta allows exactly one private reply per comment, within 7 days of the comment.

Comments reach the app two ways, both feeding the same one-row-per-comment ledger (`PrivateReply`,
unique on account + comment id), so a comment can never get two replies:

1. **Meta webhook** — `POST /api/webhooks/meta`, signature `X-Hub-Signature-256` checked with the App
   secret, deduplicated on the comment id.
2. **Per-minute poll** of the watched posts' comments with the account's own token — this is what
   makes the rule work **in Development mode, before App Review**, because Meta sends live
   `comments` webhooks only to Live apps with Advanced Access.

Outcomes (Automations → "Comments seen on watched posts", and Activity):
`DM sent` (Meta returned a message id) · `no DM` (watched post, no keyword match, or rule off) ·
`failed` (Meta refused: permission / token / validation — error text shown, owner notified) ·
`uncertain` (timeout or cut connection: Meta may have delivered it; **never re-sent automatically**,
the owner checks the inbox and presses Retry) · `queued` (rate limit or 5xx: retried, nothing was sent).

## Which login path the connected account uses
Connections → the Instagram row shows how it was connected; in the database it is
`SocialAccount.metadata.loginMethod`: `facebook_login` (Instagram linked to a Facebook Page, Page
token, host graph.facebook.com) or `instagram_login` (Business Login for Instagram, Instagram user
token, host graph.instagram.com). The steps below are for **Facebook Login**, which is what this
app's Meta setup page configures and what "Connect with Facebook login" on the Instagram row uses.
The differences for Instagram Login are listed at the end.

## 1 · Permissions to add in the Meta app (once)
Meta app → **Use cases**:
- *Manage messaging and content on Instagram* → Customize → Permissions → **Add**
  `instagram_manage_comments` (private replies + comment webhooks; Meta's private-replies page lists
  `instagram_basic`, `instagram_manage_comments`, `pages_read_engagement`).
  Optional, for reading DMs later: `instagram_manage_messages`.
- *Manage everything on your Page* → Customize → Permissions → **Add** `pages_manage_metadata`
  (needed for `POST /{page-id}/subscribed_apps`), `pages_read_user_content`, `pages_manage_engagement`,
  and `pages_messaging` (Facebook Page private replies).

Then in this app: **Connections → Meta setup** → tick **Request comments + insights permissions**
(`META_EXTENDED_SCOPES`) → Save. The app now asks for these scopes at sign-in.

## 2 · Reconnect the account (required)
Permissions are granted at sign-in, so the existing connection has to be redone once:
**Connections → Instagram row → Reconnect** (or Connect with Facebook login) → Meta's dialog now
shows the comments permissions → allow → pick the same Page + Instagram account. The account keeps
its id and rules; only the token and granted scopes are refreshed. A permission that is not added in
Meta first makes Meta reject the whole sign-in ("Invalid Scopes").

## 3 · Webhook (so Meta pushes comments; optional until App Review, see 5)
Meta app → **Webhooks** (or *Manage messaging and content on Instagram → Customize → Webhooks*):
- Object **Instagram** → *Subscribe to this object*:
  - Callback URL: `https://spagnol-social-manager.vercel.app/api/webhooks/meta`
  - Verify token: shown on **Connections → Meta setup** (generated by the app, stored encrypted)
  - Verify and save → press **Subscribe** on the field **`comments`**.
- Object **Page** → same callback URL and token → Subscribe to **`feed`** (Facebook comments).
- Then **Automations → Subscribe at Meta** next to the account: the app calls
  `POST /{page-id}/subscribed_apps?subscribed_fields=feed` with the Page token (for Instagram-via-
  Facebook-Login, Meta routes the Instagram account's webhooks through its linked Page).
- The dashboard's **Test** button next to the field sends a sample delivery to the callback; it is
  signed, so the app accepts it and (because the sample comment belongs to no watched post) records
  it as ignored.

## 4 · Who can be messaged in Development mode
Meta: "Standard Access apps can only access data for people who have a role on the app." So for the
live test in Development mode, add the second Instagram account under
**App roles → Roles → Instagram Testers** (or the person's Facebook profile under *Testers*) and
accept the invitation in the Instagram app (*Settings → Apps and websites → Tester invites*).
Comments from accounts without a role may not be delivered or may be refused with `(#10)` — the app
shows exactly that error in the outcome column instead of guessing.

## 5 · Live comment webhooks need App Review
Meta's Instagram webhooks page: the app must be **Live** and have **Advanced Access** to
`instagram_manage_comments` (and the Page `feed` field needs `pages_manage_metadata`) for real
`comments` notifications. Steps when ready: **App Review → Permissions and features → Request
Advanced Access** for `instagram_manage_comments`, `instagram_basic`, `pages_read_engagement`,
`pages_manage_metadata` (+ `pages_messaging` for Facebook), with a screen recording of this app's
Automations rule and a private reply arriving; Business Verification is part of it. Until approved,
**the per-minute poll does the same job** for the owner's own accounts (Standard Access covers the
app owner's own media), and the webhook endpoint already answers Meta's verification and Test deliveries.

## 6 · The live test (not yet done — the app has no real Instagram account connected)
1. Automations → New rule: brand, the Instagram account, pick the test post, keyword `CATALOGO`,
   reply with the catalog link, Enabled on → Save.
2. From the second Instagram account (an Instagram Tester of the app, see 4), comment `CATALOGO` on
   that post. Within a minute the row appears as *DM sent* with Meta's message id.
3. On the second account open Instagram → Messages. If it does not follow the brand, the reply is in
   **Message requests** (Instagram files first messages from non-followed accounts there).
   Expect **exactly one** message.
4. Comment `CATALOGO` again from the same account → second row *no DM*? No: a second comment is a new
   comment id, so Meta allows a new private reply — the rule answers each matching comment once. The
   guarantee is one reply **per comment**, never two for the same comment.
5. Comment `Bellissimo!` → row *no DM · no keyword match*; the account receives nothing.
6. Activity shows `automation.private_reply.sent` / `.skipped` with the comment ids.
Record the result in `docs/test-evidence/` and set `instagram.private_reply` to `LIVE_VERIFIED` in
`docs/provider-capabilities.md` only when step 3 showed one real message.

## 7 · Facebook Page Comment → Messenger (same rule editor, verify separately)
Rule with the Facebook account + a Page post. Comment event = Page `feed` webhook item `comment`,
verb `add` (or the poll of `/{post-id}/comments`). Reply = `POST /{page-id}/messages` with
`recipient.comment_id`, Page token, permission `pages_messaging` (Page role with the MESSAGING task).
Same limits: one reply per comment, 7 days; replies to another Page are impossible. Test: comment
from a Facebook profile with an app role, check Messenger (message requests if not connected).

## Instagram Login path (graph.instagram.com) — differences
Permissions in the *API setup with Instagram Login* app: `instagram_business_manage_comments`
(+ `instagram_business_manage_messages`). Webhook subscription: `POST /{ig-user-id}/subscribed_apps?
subscribed_fields=comments` with the Instagram user token (the app does this automatically when the
account's credentials carry `igUserToken`). Private reply: `POST graph.instagram.com/{ig-user-id}/messages`.
Signature: that app's App secret (`INSTAGRAM_APP_SECRET`) — the endpoint accepts either secret.
